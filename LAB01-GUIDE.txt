--------------------------------------------------------------------------------
 1. SCENARIO
--------------------------------------------------------------------------------
A small office has two departments, Sales and Ops. Each department needs its own
subnet so traffic and broadcasts stay separated. A single router connects the
two subnets so departments can still talk to each other.

--------------------------------------------------------------------------------
 2. OBJECTIVES
--------------------------------------------------------------------------------
 [ ] Build a physical star topology with two switches and one router
 [ ] Subnet 192.168.10.0/24 into two equal subnets (60+ hosts each)
 [ ] Configure router and switch basics from the IOS CLI
 [ ] Secure device access (enable secret, console password, banner)
 [ ] Assign static IP addressing to all PCs
 [ ] Verify end-to-end connectivity between subnets
 [ ] Break and fix the network on purpose, and document the results

--------------------------------------------------------------------------------
 3. EXAM OBJECTIVES COVERED
--------------------------------------------------------------------------------
 CompTIA A+       : Star topology, cable types, IPv4 addressing, default gateway
 CompTIA Network+ : Subnetting/CIDR, OSI Layer 2 vs Layer 3, ARP, routing basics
 Cisco CCNA       : IOS modes, hostname/passwords, interface config, SVI,
                    show commands, saving configs

 6. CABLING TABLE (all Copper Straight-Through)
--------------------------------------------------------------------------------
 From          | Port   | To   | Port
 --------------|--------|------|-------
 PC-A1         | Fa0    | SW1  | Fa0/1
 PC-A2         | Fa0    | SW1  | Fa0/2
 PC-B1         | Fa0    | SW2  | Fa0/1
 PC-B2         | Fa0    | SW2  | Fa0/2
 SW1           | Gi0/1  | R1   | Gi0/0
 SW2           | Gi0/1  | R1   | Gi0/1

 Why straight-through? You are connecting unlike devices (PC to switch,
 switch to router). A crossover cable is for like devices (switch to switch,
 PC to PC, router to router). Modern gear auto-negotiates this with Auto-MDIX,
 but the exams still test the rule.

--------------------------------------------------------------------------------
 7. SUBNETTING WORK
--------------------------------------------------------------------------------
 Given      : 192.168.10.0/24
 Requirement: 2 equal subnets, at least 60 usable hosts each

 Step 1 - Hosts needed: 60 -> 2^6 = 64 addresses (64 - 2 = 62 usable). OK.
 Step 2 - Host bits = 6, so network bits = 32 - 6 = 26  ->  /26
 Step 3 - Mask: /26 = 11111111.11111111.11111111.11000000 = 255.255.255.192
 Step 4 - Block size (magic number) = 256 - 192 = 64

 Subnet | Network          | Usable Range                    | Broadcast
 -------|------------------|---------------------------------|---------------
 A      | 192.168.10.0/26  | 192.168.10.1  - 192.168.10.62   | 192.168.10.63
 B      | 192.168.10.64/26 | 192.168.10.65 - 192.168.10.126  | 192.168.10.127
 (spare)| 192.168.10.128/26 and 192.168.10.192/26 are unused, kept for growth

 9. STEP-BY-STEP BUILD
================================================================================

---- STEP 1: PLACE DEVICES (5 min) ---------------------------------------------
 1. Network Devices > Routers > 2911  -> drag onto workspace. Rename: R1
 2. Network Devices > Switches > 2960 -> drag 2. Rename: SW1, SW2
 3. End Devices > PC -> drag 4. Rename: PC-A1, PC-A2, PC-B1, PC-B2
    (Click the device label to rename it, or use Config tab > Display Name)

---- STEP 2: CABLE DEVICES (5 min) ---------------------------------------------
 1. Connections (lightning bolt) > Copper Straight-Through (solid black line)
 2. Follow the Cabling Table in Section 6 exactly.
 3. Tip: Options > Preferences > check "Always Show Port Labels in Logical
    Workspace" so you can see port names on the diagram.
 4. Router links show RED until you run "no shutdown". Switch-to-PC links
    turn amber then GREEN after ~30 sec (Spanning Tree). That's normal.

---- STEP 3: CONFIGURE R1 (10 min) ---------------------------------------------
 Click R1 > CLI tab. If asked "Would you like to enter the initial
 configuration dialog? [yes/no]:" type  no  and press Enter.
 Then paste the R1 config (Section 10).

---- STEP 4: CONFIGURE SW1 AND SW2 (8 min) -------------------------------------
 Click SW1 > CLI tab > press Enter > paste SW1 config (Section 10).
 Repeat for SW2 with the SW2 config.

---- STEP 5: CONFIGURE PCs (5 min) ---------------------------------------------
 For each PC: click PC > Desktop tab > IP Configuration > select Static.
 Enter IP Address, Subnet Mask, Default Gateway from Section 8.
 (DNS server: leave blank.)

---- STEP 6: VERIFY (10 min) ---------------------------------------------------
 Run every check in Section 11. Fill in the Results column.

---- STEP 7: BREAK / FIX (10 min) ----------------------------------------------
 Run the scenarios in Section 12. Write your prediction BEFORE testing.

---- STEP 8: DOCUMENT AND SAVE (5 min) -----------------------------------------
 1. File > Save As > lab01.pkt
 2. Screenshot the topology -> screenshots/topology.png
 3. On each device run:  show running-config
    Copy the output into configs/R1-running.txt, SW1-running.txt, SW2-running.txt
 4. Fill in Sections 13 and 14.

---- What each command does ----------------------------------------------------
 enable                      User EXEC (>) -> Privileged EXEC (#)
 configure terminal          Privileged EXEC -> Global config (config)#
 hostname R1                 Names the device (shows in the prompt)
 no ip domain-lookup         Stops IOS from trying DNS when you mistype a command
 enable secret class         Hashed password to get into privileged mode
 service password-encryption Weakly encrypts plain-text passwords in the config
 banner motd #...#           Legal warning shown at login
 line console 0              Physical console port settings
   password / login          Requires a password at the console
   logging synchronous       Stops log messages from interrupting your typing
   exec-timeout 15 0         Logs out after 15 min idle
 interface g0/0              Enter interface config mode
   ip address X Y            Assign an IP and mask
   no shutdown               Router ports are OFF by default - this turns them on
 interface vlan 1            Switch Virtual Interface (SVI) - gives the switch an
                             IP for management (switches are Layer 2; this IP
                             is only for reaching the switch itself)
 ip default-gateway X        Lets the switch reply to management traffic
                             from other subnets
 copy run start              Saves RAM config (running) to NVRAM (startup)

 12. BREAK / FIX SCENARIOS
================================================================================
 Write your PREDICTION first, then test, then write the RESULT and the FIX.

 --- Scenario 1: Missing default gateway ---
 Break : On PC-B2, delete the Default Gateway. Ping PC-B2 from PC-A1.
 Predict: _i predict an arp request to be created on the next ping__________________
 Result : ___ping timed out___________________________________________________________
 Why    : PC-A1's request reaches PC-B2 (R1 routes it), but PC-B2 can't send
          the reply to a different subnet without a gateway -> Request timed out.
          PC-B2 can still ping PC-B1 (same subnet).
 Fix    : Re-enter gateway 192.168.10.65

 --- Scenario 2: Router interface shut down ---
 Break : R1(config)# interface g0/1   ->   shutdown
         Ping PC-B1 from PC-A1.
 Predict: _assuming failed ping______________________________________________
 Result : ___Desination host unreachabel_____________________________________
 Why    : R1 no longer has a route to 192.168.10.64/26 and replies
          "Destination host unreachable". Check show ip int brief:
          "administratively down".
 Fix    : interface g0/1  ->  no shutdown

 --- Scenario 3: Wrong subnet mask ---
 Break : On PC-A2, change the mask to 255.255.255.0 (/24). Ping PC-B1.
 Predict: ____that no traffic would go out______________________________
 Result : ______it did not fail completely______________________________
 Why    : With /24, PC-A2 thinks .74 is on its OWN subnet, so it ARPs for it
          directly instead of sending to the gateway. Nobody on LAN-A answers,
          so it fails.
 Fix    : Set the mask back to 255.255.255.192

 --- Scenario 4: Wrong cable type ---
 Break : Replace the SW1-to-R1 cable with Copper Cross-Over.
 Predict: _____this should have traffic fail___________________________
 Result : _____traffic did fail________________________________________
 Note   : Packet Tracer may still bring the link up (Auto-MDIX on Gi ports).
          For the exam: unlike devices = straight-through.
 Fix    : Replace with Copper Straight-Through

 14. LESSONS LEARNED / REFLECTION
================================================================================
 1. What was the hardest part?
    Remembering that the console, VTY and enable passwords are separate, and that VTY needs its own password.

 2. Why does a switch need a default gateway but not an IP on every port?
    ____to be able to remote in, ports forward traffic on MAC Address___________

 3. What would change if Sales grew to 100 hosts?
    (Hint: /25 = 126 hosts. Would the Ops subnet need to move?)
    Sales at 100 hosts needs /25, which covers .0–.127. That overlaps Ops' .64/26, so Ops would have to move, to .128/26.
