Lab 01 — Two-Subnet Office LAN

Scenario

A small office has two departments, Sales and Ops. Each department gets its own subnet so traffic and broadcasts stay separated. A single router connects the two subnets so departments can still talk to each other.

TopologyStar: 4 PCs, two 2960 access switches, one 2911 router
Addressing192.168.10.0/24 split into two equal /26 subnets (62 usable hosts each)
SecurityEnable secret, console login, MOTD banner, password encryption
Troubleshooting4 break/fix scenarios documented with predictions and root causes

All links are copper straight-through: unlike devices (PC→switch, switch→router). Crossover is for like devices — modern Auto-MDIX makes the lab work either way, but the rule is what the exams test.

Subnetting Work

Given 192.168.10.0/24, requirement: 2 equal subnets with at least 60 usable hosts each. 60 hosts → 26−2 = 62 usable → 6 host bits → /26 (mask 255.255.255.192, block size 64).

C = connected, L = local (the router's own IP). No static or dynamic routing is needed — R1 is directly connected to both subnets. The first cross-subnet ping often drops 1–2 packets while ARP resolves; the second run is 100%.

Each scenario was worked with the CompTIA 7-step troubleshooting method: identify → theory → test → plan → implement → verify → document.

Lessons Learned

  • Console, VTY, and enable passwords are separate — VTY needs its own password line.
  • A switch needs a default gateway only for management traffic to leave its subnet; forwarding itself is pure Layer 2 MAC learning.
  • Growth planning matters: 100 Sales hosts forces a /25 (.0–.127), which overlaps Ops at .64/26 — Ops would have to move to .128/26.
