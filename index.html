Break / fix — prediction before test

ScenarioPredictionResult & lesson
Missing default gateway on PC-B2 ARP request fires on next ping, then silence Ping timed out. R1 routes the request over, but PC-B2 has no gateway to reply to a different subnet. Same-subnet pings still work.
R1 Gi0/1 shutdown Ping fails Destination host unreachable. R1 loses its connected route to 10.64/26; show ip int brief shows "administratively down". Fix: no shutdown.
Wrong mask on PC-A2 (/24 instead of /26) No traffic goes out Did not fail completely at first. With /24, PC-A2 thinks .74 is local and ARPs on LAN-A instead of using the gateway — nobody answers. Fix: restore 255.255.255.192.
Crossover cable SW1 → R1 Traffic fails Traffic failed. Packet Tracer may still bring the link up (Auto-MDIX on Gi ports) — for the exam: unlike devices = straight-through.

Key takeaways

  • Console, VTY, and enable passwords are separate — VTY needs its own password.
  • A switch needs a default gateway only for remote management; its ports forward on MAC address (Layer 2). The mgmt SVI exists so you can reach the switch itself.
  • Growth check: if Sales grows to 100 hosts it needs /25 (.0–.127), which overlaps Ops' .64/26 — Ops would move to .128/26.
  • Router ports are off by default; no shutdown brings them up. Amber switch links are Spanning Tree settling — wait for green.
